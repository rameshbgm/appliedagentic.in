    One agent or a team of agents?

    Some tasks need a specialist, some need a team, and some need a whole department. How to tell which one you are building.

    step 01 · context

    Five kinds of agent

    Before combining agents, it helps to know what each kind can do alone. Think of them as skill levels for AI employees.

    Reflex agents follow rules

    A smoke detector senses smoke and rings. It doesn't know why there is smoke and doesn't plan what happens next.

    observation · real-world example

    A robot vacuum is a model-based agent. It maps your home, remembers which rooms are clean, and skips them next time.

    step 02 · reasoning

    When one agent is enough

    One agent is easier to build, test and observe. If the job fits in one context window and needs one set of tools, more agents mostly add latency and failure points.

    Split the work when the work splits. Not when the demo needs drama.

    step 03 · action

    Teams of agents

    Multi-agent systems give each agent a narrow role: planner, researcher, writer, reviewer. A supervisor routes work and decides when the job is done.

    # supervisor loop, simplified
while not task.done:
    step = planner.next(task)
    worker = route(step, ["research", "write", "review"])
    result = worker.run(step)
    task.observe(result)
    step 04 · answer

    Choosing your architecture

    Start with one agent. Measure where it fails. Add a second agent only for the part that fails for a reason a specialist would fix, such as a different toolset or a long-running subtask.
