    One agent or a team?

    Some tasks need a specialist, some need a team, and some need a whole department.

    14 min2,418 reads12 Oct 2026

    When you picture an AI agent, you might imagine one clever system that handles everything. In practice, choosing between one agent and a team of agents is one of the biggest design decisions you will make.

    Five kinds of agent

    Before combining agents, it helps to know what each kind can do alone. Think of them as skill levels for AI employees.

    Reflex agents follow rules

    A smoke detector senses smoke and rings. It doesn't know why and doesn't plan what happens next.

    Real-world example

    A robot vacuum is a model-based agent. It maps your home, remembers which rooms are clean, and skips them on the next run.

    When one is enough

    One agent is easier to build, test and watch. If the job fits in one context window and needs one set of tools, extra agents mostly add delay and new ways to fail.

    Split the work when the work splits.

    Teams of agents

    Multi-agent systems give each agent a narrow role. A supervisor routes the work and decides when it is done.

    SingleFocused tasks with one toolset.
    SupervisorResearch and reports. Can bottleneck.
    HandoffSupport triage. Watch for loops.

    How to choose

    Start with one agent. Measure where it fails. Split out a second agent only for the part that needs a different toolset or runs for a long time.
